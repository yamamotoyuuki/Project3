# コミット＆プッシュ

変更内容を確認し、コミットメッセージを生成または受け取ってGitHubにプッシュしてください。

## 引数
$ARGUMENTS

引数がある場合はそれをコミットメッセージとして使用する。
引数がない場合は変更内容からメッセージを自動生成する。

---

## 実行手順

### ステップ1: 変更状態の確認
以下を実行して現在の状態を把握する。

```
git status
git diff --stat
```

**変更がない場合:** 「コミットする変更がありません」と報告して終了する。

---

### ステップ2: 変更内容をユーザーに提示する
変更ファイルの一覧（新規・変更・削除）と変更行数の概要を表示する。

---

### ステップ3: 全変更をステージングする

```
git add -A
```

---

### ステップ4: コミットメッセージを決定する

**引数が指定されている場合:**
引数（$ARGUMENTS）をそのままコミットメッセージとして使用する。
末尾に以下を追記する:
```
Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
```

**引数が空の場合:**
`git diff --cached` の差分内容を分析し、以下の Conventional Commits 形式で自動生成する。

```
<type>(<scope>): <subject（日本語・50文字以内）>

<body（変更の背景・詳細。複数ファイルにまたがる場合のみ記載）>

Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
```

type の選択基準:
| type | 使用場面 |
|------|---------|
| feat | 新機能・新画面・新API |
| fix | バグ修正・不具合対応 |
| docs | ドキュメント・コメントのみの変更 |
| style | フォーマット・空白・セミコロン等（動作に影響なし） |
| refactor | リファクタリング（バグ修正・機能追加なし） |
| chore | ビルド設定・依存関係・CI等の変更 |
| test | テストの追加・修正 |

scope の例: `agent`, `frontend`, `backend`, `db`, `api`, `auth`

---

### ステップ5: コミットを実行する

```
git commit -m "<決定したメッセージ>"
```

---

### ステップ6: 現在のブランチを確認してプッシュする

```
git branch --show-current
```

取得したブランチ名でプッシュする。
- 通常: `git push origin <ブランチ名>`
- 初回（upstream未設定）: `git push -u origin <ブランチ名>`

---

### ステップ7: 完了を報告する

以下の情報を含む完了メッセージを表示する:
- コミットハッシュ（短縮形）
- ブランチ名
- 変更ファイル数
- 使用したコミットメッセージ
