# 仕様変更
## 概要
エージェントアプリから、購入／レンタル区分が「レンタル」でリクエストされた場合、対象の機器がレンタルとしてDBに登録されているかを確認する。
DBに登録されていない場合、リクエストされた情報をもとにレンタル機器を登録する。
DBに登録されている場合は、既存の更新処理を行うこと。
登録したレンタル機器は、管理者画面に実装された「レンタル管理」画面に表示するものとする。


### 対応
 1. エージェントアプリの変更
  - [x] この仕様変更に伴う管理者アプリの変更の変更はない想定。この想定が間違いないか確認すること。
        → 確認済み。エージェントはすでに acquisition_type=RENTAL を送信しており変更不要。

 2. 管理者アプリの変更
  - [x] この仕様変更に伴う管理者アプリの変更の変更はない想定。この想定が間違いないか確認すること。
        → 確認済み。レンタル管理画面は実装済みであり、自動登録されたレコードもそのまま表示される。変更不要。

 3. バックエンド処理の変更
  - [x] 想定される修正は、以下の通り。不足している場合は、指示を仰ぐこと。また、不足している作業を実施する場合は、以下のリストに追加すること。
  - [x] 改修（購入／レンタル区分が「レンタル」でリクエストされた場合、対象の機器がレンタルとしてDBに登録されているかを確認する。）
        → AgentService.registerRentalIfAbsent() で pc_acquisition_rental を pc_asset_id で検索して確認。
  - [x] 改修（DBに登録されていない場合、リクエストされた情報をもとにレンタル機器を登録する。）
        → 未登録の場合は RentalMapper.insert() で pc_acquisition_rental に自動登録。
           ベンダー情報がないため "エージェント自動登録" のシステムベンダーを自動作成して使用。
           rental_start_date=本日、rental_end_date=1年後（暫定）。管理者が後から更新すること。
  - [x] 追加（autoRegisterAsset() の戻り値を DB 再取得に変更し、pc_asset_id を含むエンティティを返すよう修正）

 4. データベースの変更
  - [x] この仕様変更に伴うデータベースの変更はない想定。この想定が間違いないか確認すること。
        → 確認済み。rental_vendor_id の NOT NULL 制約はシステムベンダーの自動作成で対応。スキーマ変更不要。
